# よりみち / YORIMICHI 再設計プラン

> いつもの道に、あたらしい目を。
> 街 → 発見 → シール → 共有 → 新しい街

この段階ではコードは変えていません。「実装に進んで」の合図のあと、下の §21 の順に少しずつ直していきます。

## 体験の一本線（全体の芯）

| なぜ | 答え | それを支える仕組み |
|---|---|---|
| なぜMapを見る？ | 開くと、近所の実在スポットに「なにそれ？」なコピーが置いてあるから | 起動したらすぐ現在地マップ、コピーのピン |
| なぜその場所へ行く？ | コピーの意味は行かないと分からない。名前も写真も伏せてある | 着くまでネタバレなし、アプリ内のナビ |
| なぜ自分で探す？ | 着くと「誰かはここで◯◯を見ていた」と分かる。まだ誰も見ていないものを見つけたくなる | 現地だけで見られるシール（置かれたものも見つかったものも） |
| なぜ撮る？ | 自分が見つけたものを持ち帰る手段が撮影だけだから | 探索モード → カメラ |
| なぜシールにする？ | 写真ではなく「見つけたモノ」だけが残る。同じ店でも人ごとに別のシールになる | AIが候補を出し、自分で選んで切り抜く |
| なぜ置く・送る？ | シールが次の人の「見る目」になり、知らない場所への招待状になるから | スポットに置く、知らない誰かに送る |
| なぜ次の街歩きにつながる？ | 届いたシールには必ず元の場所がある。「この場所を見る」からまたマップへ戻る | 受け取り → 元のスポット → 行ってみる |

## 1. 現在実装されている機能

- **検索型のおすすめ**：ホームで「今、なにしたい？」と入力 → 近所の実在スポットを最大5件 → AIがあだ名コピーを付ける
- **Places連携**：searchNearby を3系統並列で最大30件、営業中のみ、候補だけ Place Details で詳細を取る、写真はプロキシ経由
- **AIコピー**：Haiku で候補を絞り → Opus で解釈 → 表現の偏りをチェック（lint）→ 必要なら1回だけ付け直し。失敗時は「徒歩N分の、まだ知らない場所」
- **ネタバレなし**：到着まで番号・コピー・徒歩N分だけ見せる。地図上の店名も消している
- **アプリ内ナビ**：Routes API（徒歩）の経路線、GPSで追いかける、残り距離、40m以内で「このへんだよ」
- **到着後の答え合わせ**：「ここでした」で本名・写真を見せる → 「どうだった？」の3択
- **シール化**：撮影 → MediaPipe InteractiveSegmenter（タップ／自動検出）→ 白フチの型抜き → 1枚の写真から複数シール
- **採集**：シール帳（3列）と、自分のシールを載せた地図
- **保存**：IndexedDB（ローカル）＋ Supabase（匿名認証・RLS・Storage）
- **現在地**：SearchProvider が一元管理（取得・追跡・拒否時の表示）

### ボタン（途中でいただいた指示を反映）

- `border-radius` の角丸矩形はやめる。SVG path で少し歪んだ輪郭を描く。左右対称にしない
- 線：2〜3px、`stroke-linecap: round` / `stroke-linejoin: round`、黒か濃いグレー
- 3種類
  - **主CTA**：黄色い紙シール（例：行ってみる、ここで撮る、置いていく）
  - **サブCTA**：水色の手描き囲み（例：送り出す、シールを見る）
  - **軽い操作**：白地＋黒線（例：やめておく、もどる）
- 動き：ホバーで 0.5〜1° 傾く、押すと 1〜2px 沈む
- 使わないもの：強いドロップシャドウ、グラデーション、ガラスモーフィズム
- 実装：`<SketchButton variant="primary|sub|plain">`。輪郭の path を数パターン用意し、ボタンの文字から決まった1つを選ぶ（ボタンごとに形が変わるが、再描画しても形は変わらない）
### すべての「囲い」を手描き線に

カード・セクション・モーダル・入力欄・吹き出し・タブなど、囲いはすべてボタンと同じ手描き線でそろえる。

- CSS の `border` と均一な `border-radius` は使わない。`position: absolute` の SVG を中身の後ろに敷いて輪郭を描く。中身は普通の HTML レイアウトのまま
- 輪郭：四隅と辺の途中に小さな揺らぎを入れた path。左右対称にしない。角の丸みも四隅で変える
- 線：黒か濃いグレー、2〜3px、round cap / join。**同じ線を 0.6〜1px ずらしてもう1本重ね**、なぞったように見せる（2本目は少し薄く・少し細く）
- 塗り：白・生成り・淡い水色・淡い黄色
- 使わないもの：強い影、グラデーション、ガラスモーフィズム
- 形はブロックごとに少しずつ変える。`seed`（id や見出しから決める）で揺らぎを作るので、同じブロックは再描画しても同じ形のまま
- サイズが変わっても線が伸びないよう、`ResizeObserver` で実寸を測り、その寸法で path を作る（`viewBox` で引き伸ばさない）

|---|---|
| `sketchPath(w, h, seed, opts)` | 輪郭の path を作る関数（全部品の元） |
| `SketchFrame` | 中身の後ろに SVG を敷く土台。`fill` / `stroke` / `double` / `seed` |
| `SketchButton` | 主CTA（黄）・サブCTA（水色）・軽い操作（白） |
| `SketchCard` | スポットのカード、シールの詳細 |
| `SketchSection` | ページ内の区切り（見出し付き） |
| `SketchModal` / `SketchSheet` | モーダル、下から出るシート（上辺だけ手描き） |
| `SketchInput` | 入力欄・メモ欄（フォーカスで線が少し太くなる） |

## 8. 新規追加すべき機能

1. **スポットの保存と使い回し**：`spots` テーブル（google_place_id で一意、AI コピーと座標を保存）
2. **起動したらすぐ地図**：現在地のまわりのスポットを取得。DB になければその場で AI が作って保存
3. **スポットページ**（2段構成）
4. **探索モード**：到着したら見られる。ここで見つかったシール・置かれたシールを見せる
5. **観察（Observation）**：元の写真・選んだモノ・短いメモ
6. **AI の写真認識**：写真の中のシール候補（名前と位置）を Claude Vision で返す
7. **シールを置く**（`placed` の状態と、スポットで見られる一覧）
8. **送り出す／受け取る**（`sticker_transfers` と受信箱）
9. **マイページ**：行った場所・残した・受け取った・送り出した
10. **スポットの保存（気になる）**
11. **みちびの「観察のきっかけ」**：探索モードで「探してもない」ときだけ、ひとこと出す
12. **手描きの UI 部品**：SketchButton、SketchCard、紙の質感、新しい鳥

## 10. コアループ

**街 → 発見 → シール → 共有 → 新しい街**

1. **街**：地図にコピーが置いてある。「なにそれ？」
2. **発見**：行く。着くと、誰かの視点（置かれたシール）が見える。自分は別のものを探す
3. **シール**：撮る → AI が候補を出す → 自分で選ぶ → シールになる
4. **共有**：その場所に置いていく／知らない誰かへ送る
5. **新しい街**：届いたシールから知らない場所を知る → 行ってみる

ユーザーが増えるほど、スポットには「ここで見つかったもの」がたまり、AI の種がいらなくなっていく。

## 14. データ構造

ユーザーのたたき台をもとに、今のスキーマ（`stickers` の photo_url と sticker_url を分ける、など）を活かして整理します。

```sql
users            id, nickname, avatar, current_area, last_active_at, created_at

spots            id, google_place_id (unique), name, lat, lng, category, types[],
                 opening_hours jsonb, photo_ref,            -- Places から（取り直しできる最小限）
                 ai_copy, ai_copy_form, ai_michibi_line,    -- よりみちの層
                 ai_copy_model, ai_generated_at,
                 found_summary,                             -- 見つかったものの AI まとめ（シールが増えてから）
                 area_key (≈ geohash 6), created_at

spot_saves       user_id, spot_id, created_at               -- 気になる
visits           id, user_id, spot_id, arrived_at, method ('gps'|'manual')

observations     id, user_id, spot_id, visit_id, original_photo_path,
                 selected_object (label), bbox jsonb, memo, created_at

stickers         id, observation_id, spot_id, owner_id, creator_id,
                 cutout_path (透過PNG), processed_path (加工済み), rotation,
                 label, memo,
                 origin ('found'|'received'),                -- 獲得方法
                 status ('kept'|'placed'|'sent'),            -- 共有状態
                 placed_spot_id, created_at

sticker_transfers id, sticker_id, sender_id, receiver_id,
                 method ('random'), status ('delivered'|'opened'|'saved'),
                 created_at, opened_at
```

- **送り出す**ときは、元のシールは送った人の帳面に `sent` として残し、受け取った人には `origin='received'` の**複製**を作る。画像は同じファイルを参照する（シール帳が「消える」体験にしない）
- 公開範囲（RLS）
  - `placed` のシール：誰でも読める。ただし画像を見せるのはサーバー側で「近くにいる」と確認したときだけ
  - `observations.original_photo`：本人だけ
  - `spots`：誰でも読める。書き込みはサーバー（service role）だけ

## 15. シール生成のロジック

```
写真（端末）
 ├─ ① 縮小して /api/sticker/detect へ（Claude Vision、Opus 5）
 │     → [{label:"古い照明", box:[x,y,w,h], point:[x,y]} × 3〜6]  ※ラベルは短い名詞
 ├─ ② 候補を写真の上に枠で表示。ユーザーが 1 つ選ぶ（自分でタップして追加もできる）
 ├─ ③ 端末内の MediaPipe に、選んだ点（と枠）を渡して切り抜き（今の cutter.ts）
 │     失敗 → remove.bg → 枠で切り出す
 ├─ ④ 加工（render.ts を拡張）
 │     白フチ（今の型抜き）→ 手描き風の輪郭（少し揺らした黒線）
 │     → 軽い色補正（彩度 −8%、少し暖かく）→ 紙の質感を重ねる
 └─ ⑤ observation と sticker を保存（オフライン時は IndexedDB に置き、あとで同期）
```

- **AI が決めるのは「候補」だけ**。どれにするかは人が選ぶ
- 候補の順番は「その場所らしいもの」を上に。ほかの人がこのスポットで撮ったラベルと重ならないものを少し上げる（同じものばかりにならないように）
- 認識が失敗したとき：今の自動検出（AUTO_POINTS）とタップだけで続けられる

## 16. 「スポットに置く」ロジック

- 置けるのは、**自分がそのスポットで作ったシールだけ**。その場所で見たものが、その場所に残る
- **置けるのは、そのスポットの 150m 以内にいるときだけ**（到着の記録があれば 24 時間はどこからでも可）
- 1人が1つのスポットに置けるのは3枚まで
- 見られるのは現地だけ
  - スポットシート（行く前）：「誰かが何かを置いています（3）」と、ぼかしたシルエットだけ
  - 探索モード（到着後）：シールとメモが見える。「この人はここを見ていた」
  - そのあと「あなたは何を見つける？」と、撮るボタンへ
- 置いた人のほうには「あなたのシールを 2 人が見ました」と返ってくる（数だけ。誰かは出さない）
- API：`POST /api/stickers/:id/place`（サーバーで距離を確認）、`GET /api/spots/:id/placed?lat&lng`（近くのときだけ画像の URL を返す）

## 17. 「知らない人へ送る」ロジック（MVP：少しだけ条件のあるランダム）

```
receiver = 次の条件を満たす人の中からランダムに 1 人
  ・送った本人ではない
  ・直近 14 日に使っている
  ・そのシールのスポットにまだ行っていない
  ・直近 24 時間でまだ何も受け取っていない（1 人に偏らない）
  ・同じシールをすでに持っていない
  ・可能なら別のエリア（area_key の先頭 4 桁が違う）の人を優先
該当する人がいない → 「届け先を探しています」のまま保留し、次に誰かが開いたときに配る
```

- 1 日に送り出せるのは 3 枚まで
- **送った人にも返ってくる**：1 枚送ると、自分の受信箱にも誰かのシールが 1 枚届く（交換型。最初は同じランダムで選ぶ）
- 送り主は「知らない誰か」とだけ表示する。ニックネーム・プロフィール・フォロー・DM はない。見えるのはエリア名（例：藤沢市のあたり）まで
- 通知：アプリを開いたときに届いた順に1枚ずつ見せる（プッシュ通知は MVP では作らない）
- API：`POST /api/stickers/:id/send`、`GET /api/inbox`、`POST /api/inbox/:id/open|save`。配る処理は Supabase の RPC（`deliver_sticker`）にまとめ、同時に送られても重ならないようにする

## 18. 画像認識 / 切り抜きの実装方針

| 段階 | どこで | 使うもの | 理由 |
|---|---|---|---|
| 候補を見つける | サーバー | Claude Vision（`/api/sticker/detect`、構造化出力で label と bbox を返す） | 「照明」「砂糖入れ」のような意味のある名前が付けられる。日本語のラベルがそのままシール名になる |
| 切り抜く | 端末 | MediaPipe InteractiveSegmenter（今のまま） | 無料・速い・写真を外に出さない |
| 予備 | サーバー | remove.bg（今のまま、キーがあるとき） | 端末で失敗したとき |
| 最後の予備 | 端末 | 枠で切り出す＋角丸の紙 | どんなときでもシールはできる |
| 加工 | 端末 | Canvas（render.ts を拡張） | 白フチ・手描きの輪郭・紙の質感 |

- 送るのは縮小した JPEG（長い辺 1024px）だけ。元の写真は本人の Storage へ
- Claude の座標のずれは、MediaPipe に「点」として渡すことで吸収する（枠の中心、かつ中心付近の複数点）

## 19. MVP で作る範囲

1. 起動するとすぐ地図（目的の入力なし）＋ AI コピーのスポット（DB に保存して使い回す）
2. スポットシート（コピー・徒歩・置かれたシールの数・行ってみる）
3. ナビ → 到着 → 探索モード（答え合わせ、置かれたシール）
4. 撮影 → AI の候補 → 選ぶ → 切り抜き → 手描き風シール → メモ
5. どうする？（残す／置く／送る）
6. 置いたシールを現地で見る
7. ランダムに送る・受け取る（受信箱、元のスポットへ）
8. シール帳（すべて／スポット別）、シールの詳細
9. マイページ（簡単な履歴 4 つ）
10. 新しい見た目（鳥、手描きのボタン、紙、白・生成り・黒・水色・黄色）

## 20. MVP では作らない範囲

- プッシュ通知、リアルタイム通知
- フォロー、DM、プロフィールページ、いいね、ランキング
- 手の込んだ配送（関心の近さ、時間帯など）
- スポットの AI まとめ（`found_summary`）は、テーブルに枠だけ用意して生成はあとで
- 日付別・エリア別の並び替え（すべて・スポット別のみ）
- 自治体・商店街向けの機能（地域限定シール、イベント、管理画面）。データには `area_key` と `origin` を入れておき、あとで足せるようにしておく
- ユーザーが独自にスポットを作ること（必ず Places の実在地点）
- 通報・モデレーションの画面（MVP では、置く・送るシールを AI が画像チェックするだけにする）

## 21. 実装の優先順位

| 段階 | 内容 | 終わったらできること |
|---|---|---|
| **P0 見た目の土台** | 新しい鳥の画像、色、紙の質感、sketch 部品一式（ボタン・カード・セクション・モーダル・入力・吹き出し・タブ）、既存画面の囲いを置き換え | 全体の雰囲気が変わる |
| **P1 地図がホーム** | spots テーブル、`/api/spots/nearby`（キャッシュ → なければ AI）、ホームを地図に、スポットシート、コピーの型を広げる | 開いたらすぐ「なにそれ？」 |
| **P2 探索モード** | ナビのあと、探索モード（答え合わせを統合）、visits | 現地で探す |
| **P3 シールを作る** | `/api/sticker/detect`、候補の UI、手描き風の加工、観察メモ、observations | 人が見つけたものがシールになる |
| **P4 置く** | place API、現地だけでの表示、置いた人への反応 | 他人の視点が次の観察を生む |
| **P5 送る・受け取る** | transfers、deliver RPC、受信箱、受け取り画面 → 元のスポット | 知らない場所への招待状 |
| **P6 シール帳・マイページ** | 並び替え、詳細、履歴 | 自分の観察図鑑 |

P0〜P3 だけでも「1人で完結する体験」になります。P4〜P5 で「循環」が生まれます。
